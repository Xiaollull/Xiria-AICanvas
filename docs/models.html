Models

Model configuration uses project-relative paths below models and works unchanged on Windows and Linux. Every root may use custom names and arbitrary nesting.

The model directory

The directory follows ComfyUI's model-category naming while remaining fully owned by this project. The inference backend resolves every configured path relative to the project root on both operating systems. Checkpoints, LoRAs, upscalers, YOLO detectors, and compatible background-removal models are scanned recursively.

models/
|-- checkpoints/

|-- loras/

LoRA root files appear under 根目录; each custom first-level folder becomes a UI category and deeper folders remain visible in the model name. Moving or renaming a selected model changes its root-relative ID, so refresh and reselect it after reorganizing files.

Native Anima's Qwen3 tokenizer, tokenizer config and T5 tokenizer JSON files ship with the program under backend/resources/anima-tokenizers — they are program resources, not user model downloads. Setup, startup and program updates validate the bundled tokenizer bytes automatically, so you only download the Anima DiT, text encoder and VAE.

ADetailer detection runs on CPU in the project's verified Python environment. The UI benchmarks Hugging Face and hf-mirror routes before downloading an official model, and resumes interrupted downloads in models/yolo. Detail inpainting stays in the same environment and inherits the active checkpoint, LoRAs, sampler and scheduler. Model files are never uploaded.

model-paths.json

A program update keeps your own models/model-paths.json instead of replacing it, so custom model roots survive an upgrade. Keys you leave out fall back to the built-in defaults, which is why a file written for an older version stays correct. Only a missing file, or one the updated project could not use, is restored from the release.

The recommended-model, YOLO and background-removal catalogs are refreshed by every update, since those are the lists the program ships rather than your configuration.

Recommended-model browser

In addition to any file you place in models yourself, the browser covers:

  • Illustrious — WAI Illustrious SDXL, MiaoMiao Harem and Obsession Illustrious XL, each tracking its Civitai version list.
  • Anima — the official CircleStone Labs releases from both Civitai and the Hugging Face split_files tree, paired automatically with the shared Qwen 0.6B text encoder and Qwen Image VAE.
  • FLUX.2 — Klein 9B True V3 as Safetensors or GGUF, and the official Klein 9B KV single-file build, which is gated and needs an accepted repository licence and a Hugging Face token. Both pair with a Qwen 3 8B text encoder and the FLUX.2 VAE.
  • Krea 2 — the 12B model in Raw and Turbo variants, with a separately chosen 4B text encoder precision. Its VAE is shared with Anima.
  • Upscalers — the official Real-ESRGAN models a resample unit can enlarge with before it resizes and redraws.
FLUX.2's fp8 text encoder loads

The published fp8 Qwen 3 8B file stores 141 layers as fp8 and 85 as nvfp4. Both are decoded the way ComfyUI decodes them and expanded at load, so the smaller file is a real choice; the BF16 file remains the full-precision reference. See the support matrix below.

FLUX.1 has no recommended family: it runs from diffusion model, CLIP-L, T5-XXL and VAE files you supply yourself.

File formats

Every component loads from .safetensors. For FLUX.1, FLUX.2 and Krea 2 every component — diffusion model, text encoder and VAE — also loads from .gguf, which is the only form some quantizations are published in. Anima's components stay .safetensors.

A GGUF diffusion model or VAE keeps the checkpoint's own tensor names, the way ComfyUI-GGUF writes them, including its record of the 5-D convolution shapes ggml cannot hold. Text encoders are mostly published by llama.cpp, which renames every tensor; the families below are renamed back into ComfyUI's naming and must match the architecture the file declares. Anything else is refused by name rather than loaded partially.

Quantization, honestly

Quantized variants are offered where the publisher ships them, so the same model can be taken at bf16, fp8, mxfp8, nvfp4, int4/int8 or GGUF Q4–Q8. Each of ComfyUI's quantized layouts is read the way ComfyUI 0.33.0 reads it — the per-layer comfy_quant marker or the _quantization_metadata header table, the scales beside the weight, and whether the weight was rotated before it was quantized. The arithmetic is ported from ComfyUI and the comfy-kitchen 0.2.31 it pins rather than re-derived; the notices are in backend/resources/comfy-quant.

A layer marked full_precision_matrix_mult, or one a LoRA patches, is dequantized and multiplied at full precision instead — ComfyUI's own rule. On an NVIDIA card of SM 8.0 or newer the two integer matmuls run on built-in Triton kernels: the activation is quantized in one pass and the matmul unpacks W4A4's 4-bit weights in registers, with results bit-identical to the PyTorch port that reproduces comfy-kitchen's eager backend. They are checked against that port the first time they are used and give way to it on any failure; without Triton the port runs. On an RTX 4060 a Krea 2 block in ConvRot INT8 takes 17 ms against 40 ms at BF16 and 73 ms on the port. An installed comfy-kitchen is used in their place but is never installed by this program, and XIRAI_QUANT_TRITON=0 turns the kernels off. The path each layout takes on the current card is published as capabilities.quantization in the performance payload.

Whether a quantized file is also smaller in memory depends on the engine, because it depends on whether there is a linear op to hand the stored weight to.

EngineWhat a quantized weight costs once loaded
Krea 2 Its stored size, for every layout in the matrix above. The weight stays in the checkpoint's own type and the scale is applied inside the linear, so an fp8 diffusion model occupies about 12 GB rather than the 24 GB it expands to — the difference between resident on a 24 GB card and not — and an NVFP4 one about 7 GB.
Anima, FLUX.1, FLUX.2 The compute dtype. These mount Diffusers transformer classes through a key conversion, and the scales have no route through it yet, so the scale is folded in at load and an fp8 file costs twice what it occupies on disk.

For fp8, applying the scale at compute time is not an approximation: for every format whose weight is an ordinary matrix scaled by one number, it lands on the same bits as folding it at load, which is what makes deferring it free rather than a trade. A quantized layer a LoRA patches keeps its storage too — the adapter is carried beside the weight instead of being fused into it.

GGUF is always expanded

A GGUF block format has no compute-time form to keep, so it is expanded to the compute dtype while loading whichever engine reads it: a Q4_K file is a much smaller download and the same size in memory as bf16. VRAM there is bought by the memory mode and block-level offload, not by the file format.

The loaded size is measured from the tensor shapes and their stored types rather than the file size, so a Q4_K model is budgeted as what it becomes and an fp8 Krea 2 model as what it stays.
