Generating images

All seven engines share one sampler vocabulary and one gallery, and every engine but MOSS shares one prompt grammar. What differs is which guidance method applies and what the schedule behind a sampler name actually is.

Prompt weights

Every engine except MOSS shares the core ComfyUI parenthesis grammar. MOSS reads the prompt as written, so the brackets below reach its text encoder as literal text:

SyntaxEffect
(text)Applies the default 1.1 emphasis.
((text))Multiplies nested emphasis.
(text:1.25)Applies an explicit finite weight.
\(text\)Keeps literal parentheses.

Square-bracket de-emphasis, BREAK, textual-inversion tags, Prompt LoRA tags and A1111 scheduling syntax are not interpreted by this grammar. Anima parses Qwen and T5 token boundaries independently and applies weights to the T5-aligned LLM-adapter output.

Prompt length

There is no length limit on a prompt on any engine but MOSS. A prompt is encoded at whatever length it tokenises to: a long one costs a little more time in the text encoder and nothing else, and it is never truncated, never rejected, and never a reason a generation refuses to start. MOSS's encoder stops at 4096 tokens; its row below and the layout limits say what happens past that.

EngineWhat a long prompt does
SD, iLCLIP is encoded in 75-token blocks and the blocks are joined, which is what ComfyUI does. The block count is reported under the prompt after each run.
AnimaQwen and T5 both run at the prompt's own length. Below 512 tokens the sequence is padded up to it and the padding is masked.
FLUX.1T5-XXL carries the conditioning and runs at the prompt's own length. CLIP-L contributes only a pooled vector and reads the first 77 tokens, because that is how many position embeddings it has — the same vector ComfyUI takes from its first block.
FLUX.2, Krea 2The language model runs at the prompt's own length. FLUX.2 pads up to its trained 512-token context; Krea 2 pads nothing.
MOSSQwen3.5-9B reads the prompt inside its chat template at the prompt's own length, up to 4096 tokens including the template; a longer prompt is truncated and the run says so. Weight syntax such as (word:1.2) is passed as literal text.

The counter under each field is a character count, not an allowance. What a prompt actually costs is tokens, and that number is reported after a run alongside the block count.

A prompt is part of the attention sequence, so a very long one raises what a sampling pass needs. On the three engines that place a whole transformer on the card — FLUX.1, FLUX.2 and Krea 2 — a pass that no longer fits is retried with the transformer streamed a block at a time rather than abandoned: the picture still arrives, and the run reports LOW_VRAM instead of the mode it started in. The seed is unaffected, because the retry restarts from the same noise. Measured on a 24 GB card at 1024×1472, Krea 2 stayed resident to roughly seven thousand prompt tokens and finished a 13,849-token prompt on the streamed path in about two and a half minutes against forty seconds.

MOSS coordinate layouts

Besides plain text, MOSS-Image reads a layout: a JSON prompt holding a description of the whole picture and a list of boxes, each with a label, a description and its place on the canvas, as the official README documents. On the MOSS engine the prompt header carries a 文本 | 布局 switch. In layout mode the positive prompt becomes a card with a preview of the boxes, the count per label, the token count and whether the layout is valid, and 编辑布局 opens the layout editor. The text prompt is kept, so switching back restores it, and 转为文本 turns the layout into an ordinary text prompt.

LabelUse
物体 objectA thing in the picture.
人物 characterA person or character.
文字 textLettering. Its exact text, line breaks included, is what the model is asked to render.
画面 panelA frame: a comic panel, a background region or the whole canvas. Drawn dashed; the boxes inside it stay reachable, and it is moved by its tag.

The editor. Drag on empty canvas to draw a box, move boxes, resize them with the eight handles (Shift keeps the ratio) and let them snap to the canvas edges, centre and thirds and to other boxes; hold Ctrl to place freely. The list on the left is the reading order and the JSON order: drag to reorder, hide a box (hidden boxes are not sent) or lock it. The inspector edits the picture's description (画面), the selected box (元素: label, description, exact text, coordinates, tags, colours) and the readable JSON. Coordinates are top-left pixels on the generation canvas. A reference image can be shown under the boxes; it stays in the browser and is never uploaded. Templates (the official README example and an empty canvas), import of a readable draft or an official compiled layout, export, undo/redo and keyboard shortcuts (V/B/H, Ctrl+Z, Ctrl+D, Delete, arrows, Space to pan) are in the header and the toolbar. Below 900 pixels wide the canvas, the list and the inspector become three tabs.

What is sent. The layout is compiled exactly as the official compile_prompt.py compiles it — centred abs_centralized / yxyx boxes in compact JSON — and the server refuses a prompt that differs from its own compile. The LoRA group's prompt and the active positive presets go on a line before the JSON. The layout follows the canvas size on the Basic page: changing the size rescales every box, with an undo. Each Hires redraw recompiles the layout at its own size. An ADetailer unit with an empty prompt receives the boxes that overlap its crop, mapped onto the crop (or the picture's description when none does); [PROMPT] in a unit prompt is replaced by that text, and any other unit prompt is used as written.

Limits. A layout prompt is never truncated: the first pass and every Hires redraw must fit MOSS's 4096 tokens, chat template included, or generation is blocked and says by how much. The meter turns amber above 3,600. Transparent background, XYZ comparison and LoRA mix search do not take a layout in this release. The layout is written into the PNG and into Gallery cards, and 应用参数 restores it; programs that do not know it still read the compiled prompt.

New in 1.4

The compiled prompt is checked byte for byte against the official README example and compiler. Runs with the real weights that settle the prefix line and the ADetailer crop layout are still to come, so those two rules may change.

Anima uses a native Cosmos identity-self-attention branch rather than a Diffusers UNet adapter. It runs branches sequentially to keep one physical transformer forward live at a time, and propagates the same settings into native Hires and ADetailer refinement.

Adapter fusion

Native Anima adapter fusion accepts standard LoRA, static full-rank T-LoRA, linear LoHa, supported linear LoKr forms, and output-axis LyCORIS linear DoRA using dora_scale. Supported linear LoKr may also carry output-axis dora_scale. Weight zero is an exact disable.

Tucker and convolution forms, decomposed LoKr first factors, PEFT lora_magnitude_vector and lora_mid.weight fail closed rather than being silently approximated.

LoRA cards

A card is what you save about a LoRA yourself, on top of what the source lookup found: a cover image, a display name, the prompt you keep for it, tags and a private note.

Where to find it. Open Manage beside the LoRA mount section. On the Mounted tab each row carries a palette button on its right; in any category the Customise button sits under the picture, next to Look up source. For a saved combination, the Cover and effect images button in its header opens the card.

  • Cover replaces the preview downloaded from the source page. Pick an image you generated here, or upload a PNG, JPEG or WebP file. Either way it is downscaled to 1024 pixels on its longest edge and saved as a separate copy, so the original is untouched. Clearing the cover falls back to the downloaded preview.
  • Prompt is displayed and copyable, and can be appended to the positive prompt with one click. It is never added to a request on its own.
  • Combinations take effect images instead of a single cover, up to twelve. The first image in the strip is the combination's cover; “set as cover” reorders the strip.

Hovering a mounted LoRA — on Generate, on Image to image, or in the manager — opens the card at full size beside the row, or above and below it when the window is too narrow for either side. It is drawn over the page and takes no layout space of its own. A LoRA you have not customised yet still opens a card; it just says so, and points at the button that fills it in.

Cards live in state-cache/lora-cards/, beside the workspace rather than in the metadata cache, so re-running the source lookup never overwrites them and an in-place update preserves them. Images no card points at any more are deleted on the next save.

Samplers and schedulers

Anima, FLUX.1, FLUX.2 and Krea 2 offer the same 44 sampler and nine scheduler names in Generate and Gallery. The vocabulary is shared; the schedules behind it are not. MOSS offers three of the samplers.

  • Anima's nine are native Flow-shift-3 trajectories.
  • Both FLUX generations and Krea 2 run the same ModelSamplingFlux table, FLUX.2 taking its shift from the model and Krea 2 from the static shift its own model config declares.
  • MOSS offers euler, euler_ancestral and heun with the nine schedulers on ComfyUI's discrete-flow table (multiplier 1000) and its own shift, 5 by default and adjustable in the sampling panel. sgm_uniform and normal reproduce ComfyUI's double-shifted last step.

Named compatibility solver mappings are reported in task warnings and PNG sampling metadata rather than silently pretending to be a different implementation.

Image batches

Sampling parameters include two independent output controls:

  • Images per batch accepts 1–10. One Diffusers pipeline call uses num_images_per_prompt and an equal-length generator list, so all images in that batch are sampled together rather than as sequential single-image jobs.
  • Batch count accepts 1–20. Batches are queued inside one controllable job and run in order. For example, 3 images × 4 batches performs four pipeline calls and saves 12 images. The maximum task size is 10 images × 20 batches, or 200 saved images.

Seeds increase by output position across the complete job and wrap safely in the unsigned 64-bit range. The result browser groups outputs by batch and lets you select any image in the active batch; zoom and download always use the selected image. Cancelling or failing a multi-batch job removes partial outputs, while completed PNG files include their batch, image, seed and total batch settings in metadata.

XYZ comparison

Below the engine buttons, 生成模式 switches between 基础生图 and XYZ 对比生成 with the arrows or the dropdown. Switching never unloads a model, edits the LoRA mounts or cancels a job. Each engine keeps its own XYZ draft: 从基础生图同步基线 copies the current models, the composed prompt (combination words and switched-on presets included), sampling, canvas and LoRA mounts into it, and nothing changed there is written back to Basic.

配置 is the selected engine's independent XYZ draft. In XYZ mode the left rail edits its models, ordered background LoRAs, actual prompt, sampling, seed and original canvas directly — never Basic or image-to-image. XYZ engine selection restores that engine's draft without swapping Basic's engine or settings. Sync from Basic is an optional, selected-field import and leaves axes unchanged. Library combinations are copied as snapshots, not switched or edited in the library.

All active X/Y/Z lists can collapse. Expected quantity (1–256, Enter or confirmation) retains the first N entries and adds genuinely undefined cards; pending cards block preflight/start. Reducing quantity requires confirmation. Numeric fields offer Custom values or exact Staircase values: steps 12..20/2 gives five, CFG 4.0..6.5/0.5 gives six. Staircase automatically counts and read-only previews without manual cards. Field/mode/profile changes ask first; choosing the old field/mode restores its definition in this editing session. Labels/order/JSON remain under More.

Guidance uses the same always-visible Basic controls and conditional PAG settings. Four seed modes project fixed/±1 to exact uint64 per-repeat lists (modulo 2^64); each sample shares its seed across all combinations, with seed axes taking precedence. Random is drawn/frozen only by the server. Legacy fixed/random drafts retain their rules until an explicit mode click.

The LoRA instance weight axis picks its one target from the same full-catalog manager with a private temporary selection: close/cancel discards, confirm freezes the chosen instance. A target that is not mounted is added to each cell only, never to the global mounts. The weights take custom or staircase values without modifying global mounts, groups or prompts; testing several LoRAs together belongs to the LoRA mix search module, not to an axis.

Original generation canvas. The always-visible right-side canvas uses the same drag grid, arrow-key controls and presets as Basic. Its width and height are fixed for every original cell when the experiment is submitted: a 2×2 experiment at 1024×1408 produces four 1024×1408 originals when post-processing is off. Canvas overrides inside an axis, a component set or a saved LoRA profile are refused, not ignored. Inheriting the frozen post-processing chain is off by default; enabling it can change final output sizes without changing this original canvas.

结果 shows the selected server-frozen experiment, not the draft on the left. Its footer controls only that experiment; there is no new-draft Start button. Z/sample paging and screen cell size are separate from generation dimensions. Export opens only from the grid toolbar, and scaling an export never changes the original images or draft canvas. On phone the baseline rail collapses; expanding it uses page scrolling rather than a second small scroll pane.

Numeric ranges remain decimal text and seeds remain uint64 strings. A prompt is one literal value — commas are not split. Exact replacement has separate find, replace and expected-match fields. A draft saved with a retired LoRA swap, profile or multiplier axis keeps that axis's frozen definition and runs it as saved, but its values cannot be edited and the field cannot be chosen for a new axis. Advanced JSON parses on blur and retains invalid raw text. Repeat samples and concurrency are separate; only the configuration footer counts and starts a new draft. Invalid numeric/product values stay raw and block requests locally, separately from counts; server admission remains authoritative.

  • Axes. X is columns, Y rows and Z separate sub-grids; an unused axis counts as one value, so the image count is X × Y × Z × repeat samples. Axes are typed — steps, CFG or distilled guidance, sampler, scheduler, seed, guidance, PAG scale, CLIP skip, checkpoint or model components, positive and negative prompts, exact replacements and LoRA instance weight — and only those the engine really supports are offered, with X, Y and Z chosen independently. A saved LoRA model, profile or multiplier axis keeps its original definition but cannot be newly selected. 服务端预检 checks every cell the way an ordinary job is checked before anything runs.
  • Running. The experiment runs in the service, so closing the browser does not stop it, and by default it finishes one cell at a time. Concurrent images 2–10 only merges cells that differ in nothing but the seed into one real batch; the requested and actual concurrency are shown with the reason. A failing cell pauses the experiment for retry, skip or stop, and after a restart unfinished cells continue only when you choose to.
  • Results. The grid shows server-made thumbnails at stable coordinates, with placeholders for failed, cancelled and pending cells; the on-screen cell size never affects an export. Each cell opens in the image viewer workspace, downloads, joins the gallery as a card with that cell's own settings, or is applied to Basic.
  • Apply to Basic. Choose which groups to write; only the prompt is selected by default. The prompt box receives the cell's own text — combination words and switched-on preset text are left out, because Basic adds them again at generation time — and the dialog says whether Basic, as it stands, would send exactly the cell's prompt.
  • Whole-grid export. 导出整网格 PNG composes the whole experiment — every Z sub-grid and sample — into one PNG under outputs/XYZ/, at original resolution or a 1–100 % downscale made once from the originals (Lanczos3, linear light, premultiplied alpha), labelled with a bundled Chinese font and accompanied by a JSON manifest. A size over budget is refused with suggested percentages; nothing is shrunk or paginated automatically.
  • Reading a grid. The image reader recognises an XYZ grid PNG as a comparison sheet: it applies nothing by itself, can reopen the experiment, and lets you choose one cell to inspect and apply.

Post-processing chain

The 后处理增强 panel is one ordered list of stages, run top to bottom after sampling: up to eight resample units plus the ADetailer and RTX VSR stages, interleaved in any order — resample, ADetailer, resample again, then RTX, for example. Adding a unit inserts it; the arrows reorder it; each stage switches on and off on its own.

A resample unit is three optional steps: enlarge with an upscale model, resize to the target size with an ordinary algorithm, then redraw with the current checkpoint, LoRAs and prompt. Every combination is a real configuration:

Upscale modelScaleDenoiseWhat the unit does
yes> 1> 0The classic Hires.fix second pass.
yes> 10Enlarges with the model and does not redraw.
no> 10A plain image resize.
no> 1> 0Resizes, then redraws.
no1> 0A detail pass at the same size.

Sizes are exact. Each unit's target is round(edge × scale) of the image it receives, the figure ComfyUI's ImageScaleBy computes, with no rounding up to 64. A redraw still has to land on the engine's latent grid — 8 pixels for SD and Illustrious, 16 for FLUX.1, FLUX.2, Krea 2 and MOSS, 32 for Anima — so the panel shows the size the redraw will actually run at next to the target, and 精确输出尺寸 scales the result back to the exact target at the cost of one more resize. A redraw edge may be up to 8192 pixels on SD and Illustrious and 4096 on the other engines; a unit that does not redraw is held to neither limit.

The resize algorithms are ComfyUI's ImageScale set without the latent-only bislerp: Lanczos (the default, sharpest for enlarging), Bicubic, Bilinear, Area (best for shrinking) and Nearest.

A redraw inherits the main steps, CFG, sampler and scheduler unless the unit sets its own with 独立步数 and 独立 CFG and its own pickers. Its seed follows each picture's first-pass seed by default, or can be one fixed seed for every picture, or a fresh random seed per picture. Anima and Krea 2 can also redraw in USDU tiles instead of the whole frame at once. MOSS redraws the whole frame only (no USDU tiles), and the image-to-image page refuses MOSS in this release.

Settings saved before this chain existed — workspaces, per-engine settings, gallery cards and PNG metadata — open with their Hires.fix pass as the first resample unit and the old stage order kept, so an old workspace produces the run it always did.

Image viewer workspace

The local image workspace can be opened from the preview header or its empty state before any image has been generated. The upper-right 全屏 button expands the workspace to the browser window without using F11.

The history rail

The optional left image rail defaults to PNG/GIF files created since the current Web UI session started. Its explorer strip can open the configured output root, enter arbitrary nested folders, and return one level at a time. Each level displays direct child folders and direct images together, so a folder may contain both. Single-image batches appear as individual cards; multi-image batches are grouped into one card with a count badge, and opening that card reveals its images with a return button that restores the previous card scroll position.

History cards can be left-clicked to switch the active preview, dragged into the workspace, or right-clicked to add a new layer and manage deletion. Deletion offers a preview-only hide or permanent removal of the corresponding PNG source files.

Layers, snapping and guides

Layers can be moved, resized from their corner handles, and independently scaled with the toolbar or Ctrl + mouse wheel. The workspace defaults to a 16 px grid and the cell size is editable in pixels.

Grid and image-edge snapping are separate: edge snapping detects the visible bounds of nearby freeform image layers, shows alignment guides, and snaps their edges together when released. An optional edge-line panel can draw solid, dashed, dotted, double or glow lines around snapped images and template cells, with a standard color palette, the browser's screen color picker when available, and an editable line width.

Layout templates and composition

The workspace includes three recommended layouts for each image count from 2 through 9: horizontal comparison, a regular grid, and a feature-image layout. Template cells accept images dragged from the history rail or existing workspace layers. Template layouts react to image aspect ratios, and each selected cell supports image scale plus left/center/right and top/middle/bottom alignment.

Confirming a filled template creates a lossless PNG composition in the browser; the result can be edited again, copied without PNG generation metadata, deleted without saving, or saved to the current date directory under outputs. For a manually arranged group, 一键拼图 creates one lossless composite from the current visible layout. Changing edge-line settings on an unsaved completed collage restores its editable form and requires confirming it again.
