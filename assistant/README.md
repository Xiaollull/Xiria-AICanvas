# AI 助手资产目录

本目录存放 AI 助手的**内置角色**与知识库资产。它只包含数据，不包含任何可执行代码：
控制面仅读取并校验 JSON，永远不会加载或执行本目录中的文件。

```
assistant/
  personas/     内置角色（随应用发布，只读）
  knowledge/    知识库占位，当前版本未实现检索
```

## 角色存放在两个地方

| 位置 | 来源 | 可否编辑 | id 形态 |
| --- | --- | --- | --- |
| `assistant/personas/<id>.json` | 随应用内置 | **否**（更新时整目录替换） | 小写字母、数字与连字符，必须等于文件名 |
| `state-cache/assistant-personas/<uuid>.json` | 用户在「角色」界面创建 | 是 | 服务端生成的 UUID，必须等于文件名 |

分开存放正是两边都安全的原因：应用更新可以整体替换内置目录而不碰用户写的任何东西，
角色界面也永远不会去改一份下次更新就会被覆盖的文件。想以内置角色为起点，请**复制**它——
界面里的复制按钮会在 `state-cache` 中生成一份可自由编辑的副本。

绝大多数情况下不需要手写 JSON：在助手的「角色」标签页里新建、编辑、复制、删除即可。

## 角色格式

`schemaVersion` 为 `1` 或 `2`，两者都能读取。`1` 只有一段散文式的 `systemPrompt`；
`2` 在此之上增加了可以用表单编辑的结构化字段。缺失的字段一律按空处理，因此 `1` 是 `2` 的子集。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schemaVersion` | number | `1` 或 `2`。 |
| `id` | string | 唯一标识，必须与文件名一致。 |
| `name` | string | 角色名称，显示在角色库与角色选择器中。 |
| `description` | string | 一句话简介。**只用于界面显示，不会发送给模型。** |
| `traits` | object | 属性，见下表；取值不在词表内的按「不指定」处理。 |
| `specialties` | string[] | 擅长领域，最多 12 条。 |
| `rules` | string[] | 行为准则，最多 12 条，会按顺序编号后发送。 |
| `systemPrompt` | string | 自由发挥的角色提示词。 |
| `starters` | string[] | 推荐开场白，最多 6 条。**只用于界面显示，不会发送给模型。** |
| `knowledge` | array | 预留字段，始终被规范化为空数组。 |

`traits` 的取值：

| 属性 | 取值 |
| --- | --- |
| `tone` | `warm` `professional` `playful` `blunt` |
| `detail` | `concise` `balanced` `thorough` |
| `language` | `zh` `en` `follow` |
| `initiative` | `ask-first` `assume` |

格式错误的文件会被**跳过**而不是导致整个列表失败：助手仍会列出其余角色，
并在角色库下方提示有若干文件未能解析。

## 结构化字段是怎么发送的

它们不是第二份提示词，而是和 `systemPrompt` 一起被拼进**同一条**系统消息，顺序固定：

```
【角色】你现在扮演「<name>」。
<各项属性拼成的一句话>

<systemPrompt>

【擅长领域】<以顿号连接>

【行为准则】
1. <rules[0]>
2. <rules[1]>

<输出协议>
```

**只有有内容的段落才会出现**。因此一个只写了 `systemPrompt` 的角色（包括三个内置角色）
拼出来的系统消息与没有结构化字段时逐字节相同。`description` 与 `starters` 任何时候都不会出现。

角色界面里的「预览实际发送的系统提示词」调用的就是控制面在请求时调用的同一个函数，
所以预览出来的内容与真正发送的内容完全一致。

## 与提示词输出协议的关系

无论选择哪个角色，控制面都会在系统提示词末尾追加一段固定的**输出协议**
（见 `src/ai-assistant-protocol.js` 的 `PROMPT_PROTOCOL_INSTRUCTION`），
要求模型把可用的提示词放进 ```prompt / ```negative 围栏。
界面正是依据这个围栏来启用「应用到提示词」按钮。

因此自定义 `systemPrompt` 时**不需要**自己重复这段协议，也不要在其中要求模型改用别的输出格式，
否则应用按钮将无法识别结果。角色界面会直接拒绝保存包含该协议的提示词
（错误码 `persona_protocol_conflict`）。
